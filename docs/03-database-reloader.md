# Перезагрузка БД

`DatabaseReloader` управляет изоляцией тестовой БД.

## Режимы

### `dump`

- перед каждым тестом пересоздает тестовую БД (для MariaDB/MySQL и PostgreSQL сначала завершает ее сессии);
- загружает схему из дампа;
- подходит для тестов, которые меняют схему (DDL, миграции);
- самый медленный режим.

### `reset`

- схема загружается из дампа один раз на процесс (и на воркер paratest) и только если дамп изменился;
- перед каждым тестом очищаются таблицы с данными, а сдвинутые счетчики возвращаются к значениям из дампа;
- коммиты кода под тестом (отдельные соединения, воркеры) работают, как в `dump`;
- приложение, как и в `dump`, пересоздается на каждом тесте.

Подробности — в разделе «Режим reset».

### `transaction`

- не пересоздает БД;
- оборачивает тесты в транзакции (rollback/begin);
- схему готовит один раз на процесс через `reset`: если дамп не менялся, схема не пересоздается, данные очищаются;
- если dump отсутствует, автоматически делает bootstrap схемы из main БД;
- самый быстрый режим, но код под тестом не должен коммитить в отдельных соединениях.

Поддерживаемые значения режима формализованы в `DatabaseReloaderModesEnum`:

- `dump`
- `transaction`
- `reset`

Любое другое значение считается ошибкой конфигурации.

## Рекомендация

- по умолчанию использовать `transaction`;
- `reset` — для классов, где код под тестом коммитит (отдельные соединения, runtime тенанта, воркеры);
- `dump` — только для классов, которые меняют схему в тестах.

Режим на класс задается свойством `$databaseReloadMode` (`DatabaseReloaderTrait`).

## Режим reset

### MariaDB, MySQL и PostgreSQL

Драйверы DSN `mariadb` и `mysql` обслуживаются одинаково: клиент `mysql`/`mysqldump` из образа и
`MariaDbResetDriver`. Какой сервер на самом деле (MariaDB или MySQL), драйвер сброса определяет по `VERSION()`.

Подготовка схемы (один раз на процесс):

1. Берется файл дампа (`dumpDirectory`) или генерируется из основной БД.
2. Считается хеш: содержимое дампа без строк-комментариев (`--`) и пустых строк + драйвер + версия стратегии
   (`ResetReloadStrategy::VERSION`). Поэтому дамп, который генерируется заново на каждый процесс, не вызывает
   перезагрузку, если схема не менялась.
3. Если хеш совпадает с сохраненным в служебной таблице `_test_utils_reset` тестовой БД (в PostgreSQL — `public`),
   схема не пересоздается, данные очищаются. Иначе — путь `dump`, затем в служебную таблицу записываются хеш и
   эталон счетчиков.

Сброс перед тестом:

1. Проверка служебной таблицы: если ее нет (базу пересоздал класс в `dump` или человек) или хеш другой —
   снова подготовка схемы.
2. Завершение чужих сессий тестовой БД, чтобы незакрытая транзакция не блокировала очистку.
3. Очистка таблиц, в которых есть строки, и возврат сдвинутых счетчиков:
   - MariaDB/MySQL — `DELETE` одной транзакцией при `FOREIGN_KEY_CHECKS = 0`, затем
     `ALTER TABLE ... AUTO_INCREMENT = <эталон>` только для сдвинутых счетчиков. Сдвиг читается из
     `information_schema.TABLES.AUTO_INCREMENT`; MySQL 8 кеширует это значение на `information_schema_stats_expiry`
     (по умолчанию 86400 с), поэтому на MySQL соединение сброса выставляет
     `SET SESSION information_schema_stats_expiry = 0`, иначе сдвиг не виден;
   - PostgreSQL — один `TRUNCATE ... CASCADE`, затем `setval()` (или `ALTER SEQUENCE ... RESTART` для
     последовательностей, не использованных в эталоне). Учитываются все несистемные схемы.

Эталон счетчиков — значения сразу после загрузки дампа. `mysqldump --no-data` сохраняет `AUTO_INCREMENT=N`
основной БД, поэтому идентификаторы в тестах начинаются с этих значений, а не с 1 — так же, как в `dump`.

Стоимость сброса в MariaDB — около 5 мс на каждую таблицу со сдвинутым счетчиком: `ALTER TABLE ... AUTO_INCREMENT`
является DDL при любом алгоритме. Таблицы, в которые тест не писал, ничего не стоят.

Состояние (соединение сброса, хеш, эталон) хранится в статическом `ResetStateRegistry` с ключом по DSN тестовой БД:
контейнер и `DatabaseReloader` между тестами пересоздаются. `ResetStateRegistry::clear()` — для тестов.

### SQLite

Эталон — файл-шаблон рядом с тестовым файлом (`<test>.reset-template`), он готовится один раз на процесс по правилам
`dump`: копия основной БД, иначе копия существующего тестового файла, иначе пустой файл. Перед тестом тестовый файл
атомарно заменяется копией шаблона (`copy` + `rename`), файлы `-wal`/`-shm` удаляются. `:memory:` не поддерживается.
PDO SQLite по умолчанию ждет блокировку 60 с (`PDO::ATTR_TIMEOUT`), поэтому конкурентные записи в тесте ждут.

### Ограничения

- Дамп с данными (`INSERT`, `COPY ... FROM stdin`) — исключение: для такого подключения используйте `dump`.
- `reset` возвращает данные, но не схему: классы, которые выполняют DDL, оставляйте на `dump`.
- Ручное изменение схемы тестовой БД в обход дампа по хешу не обнаруживается:
  `php psb test:db:reload --mode=dump`.

## Конфиг

```php
use PhpSoftBox\TestUtils\Database\DatabaseReloaderConfig;

$config = DatabaseReloaderConfig::fromDatabaseConfig(
    databaseConfig: $databaseConfig,
    connectionNames: ['default'],
    testSuffix: '_autotests',
    dumpDirectory: __DIR__ . '/../../local/tests/dumps',
    mode: 'transaction',
);
```

Рекомендуемая схема для всех проектов:

- в `.env.testing` не переопределяйте `APP_DB_MAIN_DSN` на тестовую БД;
- держите `APP_DB_MAIN_DSN` как main (`app`, `project`, и т.д.);
- тестовая БД формируется через `testSuffix` (`_autotests` по умолчанию).

`testSuffix` должен быть непустым, если вы не задаете явное имя тестовой БД через `testDatabaseNames`.

## Подмена DSN на тестовые

Для тестового окружения используйте `DatabaseConfigSwitcher`.

```php
use PhpSoftBox\TestUtils\Database\DatabaseConfigSwitcher;

$switcher = new DatabaseConfigSwitcher($config);
$testConfig = $switcher->applyTestConfig($databaseConfig);
```

## CLI-команда

Для ручной перезагрузки тестовой БД доступна команда:

```bash
php psb test:db:reload --mode=dump --connections=default
```

Параметры:

- `--mode` — режим перезагрузки (`dump`, `reset` или `transaction`), по умолчанию `dump`.
- `--connections` — список подключений через запятую (`default,search`).

Если `--connections` не указан, команда перезагружает **все подключения**, которые описаны в `DatabaseReloaderConfig`.

Примеры:

```bash
# Перезагрузить все подключения в dump-режиме
php psb test:db:reload

# Перезагрузить только default и search в transaction-режиме
php psb test:db:reload --mode=transaction --connections=default,search

# Подготовить схему по хешу дампа и очистить данные (без пересоздания, если дамп не менялся)
php psb test:db:reload --mode=reset
```

## Параллельный запуск тестов

Для запуска `paratest` доступна команда:

```bash
php psb test:parallel --processes=4
```

Ключевые параметры:

- `--mode` — переопределить режим для всех классов (`transaction`, `reset` или `dump`): передается как
  `APP_TEST_DB_RELOAD_MODE`. Без опции переменная не передается, и каждый класс работает в своем режиме
  (`$databaseReloadMode`); переменная, заданная в окружении, наследуется.
- `--processes` — количество параллельных процессов.
- `--group` — запуск только указанной группы.
- `--exclude-group` — исключение группы (по умолчанию ничего не исключается).
- `--filter` — фильтр тестов.
- `--binary` — путь к бинарнику paratest (по умолчанию `./vendor/bin/paratest`).
- `--arg` — дополнительный аргумент для paratest (можно указывать несколько раз).

Каждому воркеру нужна своя тестовая БД (например, суффикс из `TEST_TOKEN`). Тогда классы в `reset` и `dump`
запускаются вместе с остальными одним запуском: подготовка схемы у каждого воркера своя.

Примеры:

```bash
# Весь набор одним запуском
php psb test:parallel --processes=4

# Все классы принудительно в одном режиме
php psb test:parallel --processes=4 --mode=transaction

# Исключить группу явно (как раньше делалось по умолчанию для db-dump)
php psb test:parallel --processes=4 --exclude-group=db-dump

# Передача дополнительных аргументов в paratest
php psb test:parallel --arg=--testsuite=Integration --arg=--stop-on-failure
```

## Переход на версию с режимом reset

- `php psb test:parallel` без `--mode` больше не передает `APP_TEST_DB_RELOAD_MODE=transaction`: классы работают
  в своих режимах. Для прежнего поведения — `--mode=transaction`.
- `php psb test:parallel` больше не исключает группу `db-dump` по умолчанию. Пока проект не перешел на `reset`,
  передавайте `--exclude-group=db-dump` явно.
- PostgreSQL: `dump` завершает чужие сессии тестовой БД перед `DROP DATABASE`.
- `transaction`: схема тестовой БД пересоздается только при изменении дампа; после ручных правок схемы —
  `php psb test:db:reload --mode=dump`.
- Если проект проверяет допустимые режимы сам (`dump|transaction` в базовом тест-кейсе или в определении
  `DatabaseReloaderConfig`), добавьте `reset`.
